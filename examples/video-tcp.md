---
title: TCP 三次握手
subtitle: 為什麼是三次，而不是兩次
---
> 兩台機器要用 TCP 聊天，得先確認一件事：對方真的聽得見、也說得出話。

## 兩端都在等待
```sequence
Client -> Server: SYN
Server -> Client: SYN-ACK
Client -> Server: ACK
note Client, Server: ESTABLISHED
```
> 先是客戶端開口，發一個 SYN，意思是"我想跟你建個連線"。
> [Server] 聽到了，回一個 SYN-ACK："收到，我這邊也沒問題。"
> 客戶端再回一個 ACK，說"好，那就開始吧"。
> 三句話說完，兩邊就都進入了 ESTABLISHED 狀態。

## 每一步確認了什麼
```flow LR
Client -> Server: 第一次：客戶端能發
Server -> Client: 第二次：伺服器端能收能發
Client -> *雙方確認: 第三次：客戶端能收
```
> 我們換個角度看，每一次握手到底證明了什麼。
> 第一次，伺服器端知道了：客戶端能發出訊息。
> 第二次，客戶端知道了：伺服器端收得到，也發得出。
> 可還差一件事。直到第三次，伺服器端才確認 [客戶端能收]。

## 如果只握手兩次
| 情況 | 兩次握手 | 三次握手 |
|---|---|---|
| 舊的 SYN 遲到 | no 伺服器端誤建連線 | ok 客戶端不回 ACK |
| 資源浪費 | no 空等的連線 | ok 不會建立 |
| 雙向確認 | warn 只確認一半 | ok 完整確認 |
> 那隻握兩次行不行？我們設想一個場景。
> 一個很早發出的 SYN，在網路裡繞了半天，現在才到。
> 如果只握兩次，伺服器端會當真，開好連線乾等，白白佔著資源。
> 握三次就不一樣了。客戶端一看不對，不回 ACK，這個連線也就建不起來。
